## Kompass (current focus, in order)

1. **Speed** — `best` compresses at 0.26 MB/s, `fast` at 2.86 MB/s (Silesia, Python 3.12).
   *Acceptance:* `fast` ≥ 10 MB/s and `best` ≥ 1 MB/s on Silesia total, guarantee still 0 violations.
   Ideas: skip candidates by cheap probe on a sample, drop bz2 from `fast`, pure-Python transforms only on small blocks.
2. **Real wins on text** — on 9 of 23 corpus files HP is only bz2-9 + 14 B header (alice29, dickens, mr, osdb, reymont, x-ray …).
   *Acceptance:* a text-oriented candidate (e.g. BWT-aware or dictionary preprocessing) beats bz2-9 by ≥ 1 % on Silesia `dickens`.
3. **CI green on GitHub** — matrix 3.8–3.14 + `fair-benchmark` job. *Acceptance:* first green run on the v2 PR.
4. **Memory cap in BLOCKS path** — preprocessors may allocate up to ~256 KiB beyond `max_output_size` (NIBBLE/RLE cap = 2·osz, ZLIB_LZMA +64 KiB; agy review 2026-10-31).
   *Acceptance:* peak ≤ `max_output_size + 64 KiB` for every block codec, covered by a test.
5. **Release 2.0.0** only after 1–3. *Acceptance:* README numbers regenerated by `benchmarks/fill_docs.py` from the release run.

## Genom (lessons — never deleted, only refined)

- **Never advertise numbers from self-generated data.** v1 claimed "+23 % vs LZMA" from synthetic repeats; one dataset (sensor) carried the whole lead, ties counted as wins, header overhead was subtracted ("netto"). On real files v1 was 20 % worse.
- **Compare against the strongest settings of the opponents** (xz -9e, zstd -19 --long, bz2), not weakened presets.
- **Independent blocks destroy context.** Splitting a 9.5 MB file into 128 KB blocks made it 2.4× bigger than plain xz.
- **A meta-compressor must include the best plain tools as candidates on the whole input**, otherwise it can lose to them.
- **`assert` is not validation.** `python -O` strips it; integrity checks must raise.
- **No compressor wins on all data** (counting argument). The honest promise: never worse than the best candidate + a few header bytes.
- **Contract first, then parallel agents.** A binding SPEC let four tools build core, tests, benchmark and docs at the same time; blind-written tests passed against independently written code on the first merge.
- **Verify every reviewer finding.** Of 10 findings by an AI reviewer, 3 were false (lc/lp/pb "invalid", hash-seed "nondeterminism", "broken" bench), 1 was a real bug.
- **A red CI that nobody looks at is no CI.** v1's workflow was invalid YAML for 8 months.
- **Check the shell before sending prompts through it:** unquoted heredocs execute backticks inside prompt text.
